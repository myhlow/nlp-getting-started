3  ·  The Mathematical Proof: Why the Live Leaderboard Scores Accuracy

Every introductory tutorial and the official Kaggle Overview tab state:

"Submissions are evaluated using F1-score between the predicted and ground truth."

Under standard binary F1-score for the positive class (Class 1 = Disaster):

Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1-Score  = 2 × TP / (2 × TP + FP + FN)
  • If you predict Constant 0: True Positives TP = 0, meaning Precision = 0 and Recall = 0. The theoretical F1-score is strictly 0.0000.
  • If you predict Constant 1: You capture 100% of real disasters (Recall = 1.0). With base rate Precision = 0.4297, the theoretical F1-score jumps to 0.6011.

The 1.0 Complement Rule: Unmasking the Real Engine

Now examine what Kaggle's live leaderboard actually returned when our submissions were evaluated:

Score(Constant 0) = 0.57033
Score(Constant 1) = 0.42966
Sum = 0.57033 + 0.42966 = 0.99999 ≈ 1.00000

Under binary F1, this complement property is mathematically impossible: 0.0000 + 0.6011 = 0.6011 ≠ 1.0. But under Categorical Accuracy, predicting the opposite class flips every correct prediction into an incorrect one, forcing the two scores to sum to exactly 100%:

Accuracy(All 0) + Accuracy(All 1) = (TN / Total) + (TP / Total) = (1861 + 1402) / 3263 = 3263 / 3263 = 1.0

The Airtight Conclusion: Kaggle's live public leaderboard scoring function executes accuracy_score(y_true, y_pred), not positive-class F1!

4  ·  Reverse-Engineering the Unseen Test Set

Because our baseline "radar pings" returned exact accuracy scores, we can reverse-engineer the ground-truth class distribution of Kaggle's 3,263 unseen test tweets:

  • Actual Safe Tweets (Class 0): 3,263 × 0.570334 = 1,861 tweets (57.03%)
  • Actual Real Disasters (Class 1): 3,263 × 0.429666 = 1,402 tweets (42.97%)

Compare this with our training dataset (7,613 tweets):

  • Training Class 0: 4,342 / 7,613 = 57.034%
  • Training Class 1: 3,271 / 7,613 = 42.966%

The test set split is an exact stratified mirror of the training set to the third decimal place. There is zero covariate label shift between train and test.

5  ·  Automated Termux Reproduction Script

Here is the exact script executed inside Android Termux to generate and verify all three baseline submissions:

import pandas as pd
import numpy as np

train = pd.read_csv('train.csv')
test = pd.read_csv('test.csv')
sample_sub = pd.read_csv('sample_submission.csv')

p_pos = train['target'].mean()  # 0.42966

# Baseline 1: Constant 0 (Majority)
sub_zero = pd.DataFrame({'id': test['id'], 'target': 0})
assert len(sub_zero) == len(sample_sub)
sub_zero.to_csv('submission_majority.csv', index=False)

# Baseline 2: Constant 1 (Minority)
sub_one = pd.DataFrame({'id': test['id'], 'target': 1})
assert len(sub_one) == len(sample_sub)
sub_one.to_csv('submission_constant_1.csv', index=False)

# Baseline 3: Empirical Random Prior
np.random.seed(42)
sub_rnd = pd.DataFrame({
    'id': test['id'],
    'target': np.random.binomial(1, p_pos, size=len(test))
})
sub_rnd.to_csv('submission_random.csv', index=False)

print("Generated and verified all three baseline submissions!")
