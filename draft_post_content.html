3  ·  The Mathematical Mechanics: Why F1 Collapses to 0 vs. Climbs to 0.6011

In the Kaggle Disaster Tweets competition, your submission is evaluated on the harmonic mean of Precision and Recall for the positive class (Class 1):

Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1-Score  = 2 × (Precision × Recall) / (Precision + Recall) = 2 × TP / (2 × TP + FP + FN)

In the ground-truth training set of 7,613 tweets:

  • Actual Non-Disaster (Class 0): 4,342 tweets (57.03%)
  • Actual Real Disaster (Class 1): 3,271 tweets (42.97%)

Case 1: Why Constant 0 Produces Exactly 0.0000 F1

When a model predicts 0 for every sample:

  • It never predicts 1, so it never finds a single disaster: TP = 0.
  • It never predicts 1, so it never raises a false alarm: FP = 0.
  • It gets all 4,342 non-disasters correct: TN = 4,342.
  • It misses every single real disaster: FN = 3,271.

Plugging these values directly into the count formula:

F1 = (2 × 0) / ((2 × 0) + 0 + 3271) = 0 / 3271 = 0.0000

Even though the model correctly identified 57% of all tweets (yielding 57.03% Accuracy), it detected 0% of the disasters it was built to identify. Its Recall is 0, completely zeroes out the numerator, and triggers an absolute score collapse.

Case 2: Why Constant 1 Surges to 0.6011 F1

Now consider the opposite extreme: predicting 1 (Real Disaster) for every single tweet:

  • It correctly flags all 3,271 real disasters: TP = 3,271.
  • It falsely flags all 4,342 non-disasters: FP = 4,342.
  • It never predicts 0: TN = 0.
  • It never misses a disaster: FN = 0.

Look at the resulting Precision and Recall:

Recall    = 3271 / (3271 + 0) = 1.0000 (100% Recall)
Precision = 3271 / (3271 + 4342) = 3271 / 7613 = 0.4297 (Base Rate Precision)

F1 = 2 × (0.4297 × 1.0) / (0.4297 + 1.0) = 0.8594 / 1.4297 ≈ 0.6011

The Critical Kaggle Lesson: Because Constant 1 achieves a perfect 100% Recall, the F1 formula is mathematically bounded below by 2p / (1 + p) where p is the positive class prior (0.4297). A completely dumb model that flags every tweet as an emergency scores 0.6011.

4  ·  The "False Victory" Danger in Beginner NLP

This metric asymmetry creates a dangerous psychological trap for practitioners:

If you train a machine learning model (such as a small LSTM or basic neural network) and obtain an F1-score of 0.5500, you might celebrate thinking you beat random guessing (0.4145). In reality, your model is performing significantly worse than a single line of code that predicts constant 1s (0.6011).

Therefore, in Kaggle's Disaster Tweets challenge, your real competitive baseline is not zero, nor is it random chance. Your true baseline floor is 0.6011. Any natural language processing technique worthy of production must demonstrably exceed this threshold.

5  ·  Automated Termux Reproduction Script

Here is the exact script we deployed inside Android Termux to evaluate and package all three baseline submissions:

import pandas as pd
import numpy as np
from sklearn.metrics import f1_score, accuracy_score

train = pd.read_csv('train.csv')
test = pd.read_csv('test.csv')
sample_sub = pd.read_csv('sample_submission.csv')

p_pos = train['target'].mean()  # 0.42966

# Baseline 1: Constant 0
sub_zero = pd.DataFrame({'id': test['id'], 'target': 0})
sub_zero.to_csv('submission_majority.csv', index=False)

# Baseline 2: Constant 1
sub_one = pd.DataFrame({'id': test['id'], 'target': 1})
sub_one.to_csv('submission_constant_1.csv', index=False)

# Baseline 3: Empirical Random Prior
np.random.seed(42)
sub_rnd = pd.DataFrame({
    'id': test['id'],
    'target': np.random.binomial(1, p_pos, size=len(test))
})
sub_rnd.to_csv('submission_random.csv', index=False)

print("Generated and verified all three baseline submissions!")
